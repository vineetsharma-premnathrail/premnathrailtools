# Release v0.2 — P2P Hardening

**Module:** Release Notes
**Prepared by:** Vineet Sharma
**Date:** 29 August 2026
**Covers:** 2026-08-17 (`b42759f`)

---

## 1. Summary

A consolidation release for the standalone Purchase Requisition module. The module is renamed internally from **PR Requests** to **P2P Requests** and gains the structured fields required for the multi-head approval workflow introduced in later releases.

The Service Module also gains private project attachments and richer material fields.

---

## 2. What Shipped

### 2.1 P2P / Purchase Requisition

* Renamed the underlying **PR Requests** tables and routes to **P2P Requests**.
* Added requisition **priority**, **category**, **required-by date**, and **reason** fields.
* Added a **requirement/approver** field for routing a requisition to a specific approver.
* Added attachment-to-item linking so an attachment can be associated with a specific requisition item.
* Added P2P item columns for per-item tracking.
* Added department/designation sharing fields supporting department-based approval routing.

### 2.2 Service Module (ERP)

* Added **private project attachments**, restricting visibility from users who should not have access.
* Added **model**, **budget**, and **reason** fields to Service Request materials, providing additional procurement context.

### 2.3 Platform

* Continued preparation of the `users` table for the approval-role and department-routing model that later releases build out.
