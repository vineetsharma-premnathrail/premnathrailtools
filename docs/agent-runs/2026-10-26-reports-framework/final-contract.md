# Reports framework - FINAL contract (as built by backend-agent A; authoritative over spec.md and revision 2 where they differ)

Built in `backend/app/core/reporting/` (`registry.py`, `dates.py`, `engine.py`, `xlsx.py`, `router.py`, `providers.py`, `features.py`). 35 framework tests pass. `ReportDef` has NO `run` function: modules register DATASETS (rows loader + dimensions + measures + filters + detail columns) and REPORTS (pivot or composite) on top of them.

## Module API for backend-agent B (Service definitions)
Import from `app.core.reporting`: `ReportDataset, Dimension, Measure, FilterDef, DetailColumn, DateField, ReportDef, ReportChart, ReportKpi, ReportResult, ReportCtx, register_dataset, register_report, get_dataset, get_report, module_reports, management_feature, token, NONE_TOKEN`. Aliases: `ReportFilter = FilterDef`, `ReportColumn = DetailColumn`, `ReportResult` = composite result type.
- `ReportDataset(module, key, label, record_noun, date_fields, default_date_field, dimensions, measures, filters, columns, default_sort, load, tab="reports", money_feature, id_keys)`. `load(ctx, window)` MUST start from `apply_scope(...)`; `window` is `(from, to)` already widened for the comparison period (or None); it may over-fetch because the engine re-applies the exact window, filters and search in Python; rows are plain dicts; `id_keys` (e.g. `sr_id`, `project_id`) are always carried in detail rows. `register_dataset` raises ValueError if a filter has neither `match` nor a same-key dimension, or if the default date field / default sort is not declared.
- `Dimension(key, label, value(row), label_of(row), people, money, order, time_bucket, blank_label)`. A `time_bucket` dimension buckets the chosen date field. Every non-time dimension is automatically also a filter (default match by `token(value)`).
- `Measure(key, label, type, agg in count|count_distinct|sum|avg|median|max|p90|ratio|none, field, where, ratio=(numerator key, denominator key), money, people, drill_filter, better, group)`. Dotted keys are fine. Percent and ratio values are FRACTIONS (0.25 = 25 %).
- `FilterDef(key, label, type in select|multi_select|user|entity|text|int|bool, options (static (value,label) pairs, enforce valid values), options_fn(ctx, q) -> [{"value","label"}], match(row, parsed), people, money, group)`. Parsed values: multi_select list of strings; user/entity list of ints (or "__none__"); int an int; bool a bool. Paired int filters named `x_min` / `x_max` get the swap check.
- `DetailColumn(key, label, type, default, money, link=(id key, page base), cut, width, searchable, total="sum"|"none")`. `DateField(key, label, value(row))`; key `none` with `value=None` = all dates.
- `ReportDef(module, key, label, description, section, order, kind in pivot|composite, dataset, defaults, locked_filters, money_report, needs_management, self_only_without_management, self_filter="engineer", composite(ctx) [composite only], measures, group_bys, people_group_bys, charts, definitions, tab, date_basis)`. `defaults` keys: `date_field, preset, compare, filters, group_by, group_by2, measures, columns, level, sort` (server falls back to them when the request omits them; `defaults.filters` is the client's starting state only; use `locked_filters` for always-on ones). Every composite needs a `dataset` whose filters exist (filters on composites are validated against it).
- `ReportCtx(db, user, today, date_field, d_from, d_to, filters, q, group_by, group_by2, measures, sees_money, sees_people, self_only, compare)` (`compare` is `{"kind","from","to"}` or None).
- Composite `ReportResult`: `rows, group_by, group_label, measures` (list of `Measure`, `agg="none"`, with money/people flags), `totals` (measure key -> value), `kpis` (list of `ReportKpi`), `series` (declared chart key -> `{"labels","datasets"}`), `notes`. Row shape `{key, label{group_by: text}, values, compare, delta_pct, drill, measure_drill{key: {"report": "<target report>", f_...}}, children}`. The engine strips money/people measures, KPIs and series by their flags. Detail level on a composite returns 422 (drills from composite cells name a target report with `report`).
- Provide `options_fn` for big lists (customers, machines): the default options lookup calls `load(ctx, None)` on every call.
- The `reports.management` feature is registered only in A's test fixture: B's `backend/app/core/features/erp.py` line `register_features("erp", "reports", management_feature())` makes it real.

## HTTP contract for the frontend (all under /api/v1/reports)
- `GET /{module}` catalogue: `module, module_label, can_export, sees_money, sees_people, presets[{key,label}], compare_options[{key,label}], datasets[], reports[]`. Dataset: `key, label, record_noun, date_fields[{key,label}], default_date_field, default_sort, dimensions[{key,label,people,time_bucket}], measures[{key,label,type,group,better?}], filters[{key,label,type,group,people,options|null,has_lookup}], columns[{key,label,type,default,cut,total,link?,id_key?}]`. Report: `key, label, description, section, order, kind, dataset, defaults, locked_filters, self_only, date_basis, group_bys[{key,label}], measures[] (composite-only data, empty for pivots), definitions [[metric,text]]`. Money/people items and reports the viewer may not use are ABSENT.
- `GET /{module}/{report}` run. Params: `level` (summary|detail), `date_field`, `preset`, `date_from`, `date_to`, `compare` (previous_period|previous_year), `f_<filter>=a,b`, `q`; summary: `group_by`, `group_by2`, `measures=m1,m2` (1 to 8); detail: `columns`, `sort`, `dir`, `page`, `page_size` (max 500).
  - Summary response: `level, report, label, dataset, self_only, period{date_field,date_field_label,from,to,label,compare|null}, scope_label, generated_at, filters_applied[{key,label,value,locked}], group_by, group_by2, measures[{key,label,type,better?}], rows, totals{values,compare,delta_pct}, kpis[{key,label,type,value,compare?,delta_pct?,drill,better?}], series[{key,label,kind,labels,datasets}], group_count, notes, truncated` (pivots also `record_count`). Row: `{key{dim:value}, label{dim:text}, values, compare?, delta_pct?, drill, measure_drill, children?}`.
  - Detail response: `level:"detail", ..., q, columns[{key,label,type,cut,link?,id_key?}], rows, row_count, page, page_size, sort[key,dir], totals, notes`. Rows carry the dataset `id_keys` and link id keys so RecordRefMiddleware adds `*_ref`.
  - `measure_drill[measure]` is the COMPLETE drill for that cell (row drill + the measure's own filter, intersected when both set the same filter): the client must NOT merge row drill and measure drill itself. It is `null` when the two contradict (the value is 0). A measure without `drill_filter` is absent from `measure_drill`: use the row `drill`.
  - The `drill` object holds `date_field`, `date_from`, `date_to` and `f_<dim>=<token>` entries; the client merges it into the current params with `level=detail`; a `report` key in a composite cell drill names the target report. Tokens: null = `__none__`, bool = `1`/`0`. Time-bucket groups drill with `date_from`/`date_to` clipped to the period. Caps: 1,000 level-1 groups and 200 children, with an "Others" row (no drill) and a note.
  - PERCENT and ratio values are FRACTIONS (0.25 = 25 %), including `delta_pct`. Date/datetime/time strings are IST.
- `GET /{module}/{report}/options/{filter_key}?q=` -> at most 50 `[{value,label}]` from scoped rows; people filters without management return only `[{value: <user id>, label: "Me (<name>)"}]`.
- `GET /{module}/{report}/export`: same params as run plus `sheets=summary,detail,definitions`, `include=other,report,keys`, `all_columns=1`. Included reports keep only the period, comparison and the filters valid for their dataset. A report the viewer is denied in a pack is skipped (header `X-Reports-Skipped`). Needs `{module}:{tab}:export`; writes `AuditLog(entity_type="report_export", action="exported")`. Sheets: Summary, "<label> - summary", "<label> - records", Definitions (composites have no records sheet). Header row 7, freeze at B8, SUBTOTAL starting row 8.
- Behaviours: self-only reports (`self_only_without_management`): grouping by a people dimension is allowed without management because the engine forces `f_<self_filter> = me`; on other reports a people group-by is 403. Defaults naming money/people items the viewer cannot use are silently dropped; an explicit request for one is 403. `q` matches only `searchable` columns. A `range` filter type does not exist (paired `x_min`/`x_max` int filters instead). `date_from`/`date_to` with date_field `none` are ignored. Pivots always get the auto chart (`series[0].key == "main"`); composites declare charts in `ReportDef.charts`.
