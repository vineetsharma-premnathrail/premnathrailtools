# Reports framework for every module, Service first (pilot)

Owner request (2026-10-26): in the Service module Reports: which engineer did how many services, timing, how many pending; "full detailed and deep, customisable by filters"; management can see it; export to designed Excel with a custom date-to-date range; the same Reports tab in EVERY module. Stage 1 = framework + Service (7 reports). Stage 2 = other modules plug in (later).
Size L. No migration, no new tables or columns. Architecture agent design (read-only) - this file is the spec.

## Decision
A small coded report framework in `backend/app/core/reporting/` (pattern of `settings_framework.py`): each module registers `ReportDef`s in code; ONE generic endpoint set applies tab permission, data scope, date range, whitelisted filters, group-by, column choice, sort, and removal of money / per-person figures; ONE designed .xlsx builder (lifted from `backend/app/modules/p2p/routes/mis.py`); ONE shared `ModuleReportsPage` on the frontend driven by the catalogue the API returns. Users customise only at run time (date range, filters, group-by, columns, sort, saved views in localStorage). No report definitions in the database (decision: no metadata customisation).

## Service data (no new column)
Used: `ServiceRequest.opened_at` (fallback `created_at`), `first_response_at`, `resolution_at`, `closed_at`, `expected_date_to_attend`, `expected_completion_date`, `sla_resolution_due_at` (fallback only; NEVER label it SLA, say "Target date"), `actual_date_attended`, `actual_completion_date`, `assigned_service_person_id` + `assigned_to_name` (CURRENT assignee only), `ServiceVisit` (`engineer_id`, `visit_date`, `arrive_at`, `depart_at`, `work_hours`, `travel_hours`, `km`, `travel_cost`, `stay_cost`, `misc_cost`, `customer_sign_name`, `customer_signed_at`), `status`, `priority`, `service_type`, `issue_category`, `warranty_status`, `is_chargeable`, `service_contract_id`, `billing_status` (not_billable/to_bill/invoiced/paid), money fields (`service_cost`, `transport_cost`, `accommodation_cost`, `miscellaneous_cost`, `total_material_cost`, `tax_amount`, `total_bill`, `material_cost_actual`), `Project` (serial_number, model_name, machine_type, customer_id -> crm_organizations.name, client_company, site_name, site_location, site_state, zone).
Missing (do not invent): when the SR was assigned (no per-engineer reassignment history, so per-engineer SR counts use the CURRENT assignee; visit figures use the visit's engineer), acknowledged/scheduled timestamps, cancel timestamp (cancelled SRs are excluded from timing and pending), customer_satisfaction / downtime_hours / actual_service_duration_hours (not in schemas, left out).
Derived (Python): `open_ts = coalesce(opened_at, created_at)`; `reported_on = IST date(open_ts)`; `response_h = max(0, first_response_at - open_ts)` hours; `done_ts = coalesce(resolution_at, closed_at)` only when status in (work_completed, review, closed); `resolution_days = (done_ts - open_ts)/24h`; `reach_days = actual_date_attended - reported_on`; `target_date = expected_completion_date or IST date(sla_resolution_due_at)`; `on_time = IST date(done_ts) <= target_date` (only when both exist); `OPEN = {open, acknowledged, assigned, scheduled, in_progress, pending_parts, on_hold}`; `AWAITING_CLOSURE = {work_completed, review}`; `overdue = status in OPEN and target_date < today_IST`; `days_overdue`; `age_days = today_IST - reported_on`, buckets 0-2, 3-7, 8-15, 16-30, 31-60, over 60; `visit_expenses = travel_cost + stay_cost + misc_cost`; `actual_cost = material_cost_actual + sum(visit_expenses)`; come-back = an SR opened within 30 days after the previous SR's done_ts (or open_ts if not done) on the SAME machine, excluding planned work (service_type installation_commissioning, amc, inspection_maintenance); load SRs from up to 30 days before date_from to find the previous one. IST is a fixed offset `timezone(timedelta(hours=5, minutes=30))`; bounds `[d_from 00:00 IST, d_to+1 00:00 IST)` converted to UTC; naive datetimes (tests) are treated as UTC like `sla._aware`.

## Service report catalogue (all money columns need `erp:service_requests.charges:view`; per-person aggregates need `erp:reports.management:view`)
Each report carries a `date_basis` text printed on the page header and in Excel.
1. `engineer_performance` "Engineer performance" (section Engineers). Without management: own row only, titled "My performance". Group by `engineer` (default) or `engineer_month`; plus a "Not assigned" row. Columns: Engineer; Assigned (assignee = engineer, reported_on in range); Completed (IST date(done_ts) in range); Completed on time; On-time % (on_time / completed with a target_date, weighted); Pending now (OPEN, snapshot); Overdue now; Awaiting closure; Avg response (h); Avg resolution (days); Median resolution (days); Avg time to reach site (days); Come-backs; Visits; Days on site (distinct visit_date); Work hours; Travel hours; Km; Billed value (sum total_bill of Completed with billing_status invoiced/paid, money); Visit expenses (money). KPIs: Engineers with work, Completed, On-time %, Avg response (h), Avg resolution (days), Work hours, Overdue now. Charts: stacked bar Completed/Pending/Overdue by engineer (top 15); bar Avg resolution by engineer; line Completed per month for top 5 engineers.
2. `pending_ageing` "Pending and ageing" (section Pending). `date_mode = snapshot` (date control shows "As of today", disabled; filters still apply). Group by none (list: SR No link, Reported on, Age days, Status, Priority, Type, Customer, Machine, Site, Engineer, Target date, Days overdue, Issue [cut column]) / status / age_bucket / priority / customer / engineer (management only) with columns Group, Open, Overdue, Unassigned, Avg age days, Oldest days. Rows: status in OPEN + AWAITING_CLOSURE. KPIs: Open, Overdue, Awaiting closure, Not assigned, Oldest open (days), Avg age (days). Charts: stacked bar age bucket x priority; bar by status; bar by engineer (management). Default sort Age descending.
3. `turnaround` "Response and resolution time" (section Timing). Response figures use SRs with reported_on in range; resolution figures use SRs with done_ts in range. Group by priority (default), service_type, issue_category, month, customer, zone, engineer (management only). Columns: Group; Raised; Responded; Avg response (h); Median response (h); Completed; Avg resolution (days); Median resolution (days); 90th percentile resolution (days) (`statistics.quantiles(n=10)[-1]` when n >= 2); On-time %; Avg time to reach site (days). KPIs: Avg response (h), Median resolution (days), On-time %, Completed. Charts: grouped bar of avg response + avg resolution by group; line avg resolution by month.
4. `volume` "Volume and trends" (section Volume). Basis reported_on in range (Completed column uses done_ts in range). Group by month (default), week (ISO, Monday, IST), quarter, service_type, issue_category (blank -> "Uncategorised"), priority, status, zone, site_state, warranty_status. Columns: Period/Group; Raised; Completed; Closed (closed_at in range); Cancelled; Net change (Raised - Completed); Urgent %; Chargeable %. Charts: Raised vs Completed per bucket; doughnut by type; top 8 categories bar; status doughnut.
5. `customers_machines` "Customers and machines" (section Customers & machines). Basis reported_on in range. Group by customer (default): Customer; Machines serviced (distinct); SRs; Urgent; Open now; Avg resolution (days); Come-backs; Warranty/AMC/contract SRs (is_chargeable false); Chargeable SRs; Billed value (money). Group by machine: Serial (link to the machine), Model, Customer, Site, SRs, Come-backs, Last reported on, Most frequent category. Group by model or zone: customer shape. Extra filter `min_srs` (int, default 1; 2 = repeat failures). Charts: top 10 customers bar; doughnut warranty vs AMC/contract vs chargeable.
6. `billing_cost` "Billing and cost" (section Billing). Whole report needs the money switch. Basis done_ts in range. Group by billing_status (default), month, customer, service_type, engineer (management only). Columns: Group; SRs; Chargeable; Free of charge; Service; Transport; Stay; Misc; Material billed; Tax; Total bill; Material cost actual; Visit expenses; Gross margin (total_bill - tax_amount - actual_cost); To bill; Invoiced; Paid. KPIs: Billed, To bill (count and amount), Collected, Free jobs, Actual cost, Gross margin. Charts: cost-breakdown doughnut; stacked bar by month.
7. `visit_log` "Visit log" (section Engineers). Basis visit_date in range on SRs in scope; without management only the viewer's own visits. Group none: Date; SR No (link); Customer; Machine; Engineer; Arrived and Left (IST time); Work h; Travel h; Km; Expenses (money); Customer signed (Yes/No); Work done (cut column). Group by engineer / month / customer: Visits, Days, Work h, Travel h, Km, Expenses.
Common filters (each report lists the ones it supports): `engineer` (user, people filter; options are distinct assignees + visit engineers on scoped SRs; without management only "Me"), `customer` (entity, crm org id), `machine` (entity, project id), `zone`, `site` (contains match on site_name or site_location), `service_type`, `priority`, `status`, `chargeable` (chargeable/free), `warranty_status`, `issue_category`, `billing_status` (billing only), and also the date field choice where it makes sense. Owner emphasis: DEEP and DETAILED: every summary row/number drills down to the underlying records (click opens the list of SRs behind it with the same filters carried over: implement as the same run endpoint with `group_by=none`/a `drill` filter or a row-level report, your choice, keep it simple), a row-level table for each report, active-filter strip, group by any supported field, measure choice where cheap.
