# Dashboards - FINAL contract (as built by backend-agent A; authoritative over dashboards-spec.md where they differ)

Built in `backend/app/core/reporting/` (`registry.py`, `dashboards.py`, `router.py`, `xlsx.py`, `engine.py`). 57 tests pass (22 new). Existing run/options/export endpoints unchanged.

## Catalogue: `GET /api/v1/reports/{module}` now also returns `dashboards[]`
`dashboards[]` = one entry per dashboard `{key, label, order, pages[]}`. Page: `{key, label, hint, date_mode (range|snapshot), dataset, date_field, self_only, slicers[], kpis[], visuals[]}`; `date_field` falls back to the dataset default; `self_only` is true only when the page is self-only and the viewer lacks the management switch. Slicer: `{key, label, type, people, options: [{value,label}]|null, has_lookup}` (people slicers stay and return only "Me" without management; use the existing options endpoint for lookups). Visual / KPI: `{id, kind (kpi|donut|column|hbar|line|stacked_bar|table), title, definition, dataset, is_kpi, group_by, group_by2, measure, measures, columns, top_n, span, drill, time_window, date_field, better, value_type, measure_label}`. Pages and visuals the viewer may not see are ABSENT (money_page without the money switch, people_page without management). Datasets used by pages are also in `datasets[]` (the Detailed data tab uses their columns and filters). A module with dashboards but no reports is no longer a 404.

## `POST /api/v1/reports/{module}/dashboard/{page}`
Body (JSON): `date_field?`, `preset?`, `date_from?`, `date_to?` (YYYY-MM-DD, both together, or a preset; default this month), `compare?` (`previous_period` | `previous_year`; 422 on a snapshot page), `filters: {"f_<key>": "a,b" | ["a","b"]}` (keys start with `f_` and exist in some dataset of the page; a key a visual's dataset lacks is ignored for that visual), `visuals?: [{id, filters?}]` where `filters`, when present, is the COMPLETE filter set for that visual and REPLACES the page filters (`{}` = no filters); if `visuals` is omitted every visible visual and KPI is computed. Same validation as the run endpoint (people filter naming someone else needs management: 403; bad enum/entity: 422 with the same text). Time-bucket dimensions are valid filters: `f_month=2026-09-01` (bucket start date); bad value 422 "...must be a month picked from the chart...".
Response: `{page, label, hint, dataset, self_only, period{date_field, date_field_label, mode, from, to, label, compare{kind,from,to}|null}, filters_applied[{key,label,value,locked}], scope_label, notes[], generated_at, kpis{<id>: {kind:"kpi", label, type, value, compare?, delta_pct?, better, definition, row_count, drill{dimension:null, filters{f_x:...}}}}, results{<id>: ...}}`.
Chart results (donut, column, hbar, line, stacked_bar): `{kind, labels[], tokens[], values[], datasets[{label, data[], measure?|token?}], measure{key,label,type}, measures[], totals{measureKey: value}, row_count, truncated, time_axis, drill{dimension, tokens[]}}`. Clicking label i adds `f_<drill.dimension> = tokens[i]` to the page filters (time axes use the bucket start date as the token). A stacked chart with `group_by2` adds `series_dimension`; each dataset carries its own `token`. With compare on, a category chart without `group_by2` also returns `compare[]` (aligned to labels), `totals_compare`, `delta_pct`; time axes get no compare. PERCENT and `delta_pct` values are FRACTIONS (0.25 = 25 %).
Table with `group_by` (Top N): `{kind:"table", labels, tokens, columns[{key,label,type}], rows[{label, token, values{measureKey: v}}], values, totals, drill, ...}`. Record table (no group_by): `{kind:"table", columns[{key,label,type,cut,link?,id_key?}], rows (carry id keys such as sr_id), row_count, shown, drill{dimension:null}}`.
Errors: 404 unknown page (lists page names); 403 no tab View / money page or visual without the switch (names the Charges feature) / people page, visual or filter without management; 422 unknown filter key, key without `f_`, bad dates, bad date field, unknown visual id, comparing a snapshot page; an explicitly requested hidden visual gets 403 with the real reason (omitted ones are silently skipped).
"Show data" for a chart or KPI: the page filters plus `f_<dimension>=token` (or the KPI's `drill.filters`) sent to the existing `GET /reports/{module}/{report}` with `level=detail` (a `*_explorer` pivot report of the page dataset) with the same `date_field`, `date_from`, `date_to`.

## `GET /api/v1/reports/{module}/dashboard/{page}/export`
Query: `date_field, preset, date_from, date_to, compare, f_<key>=...`, optional `visual=<id>`. Needs `{module}:{tab}:export`. Full export: Summary sheet (title band, period, filters, "Data: your access", "Generated ... by ...", KPI scorecard with change), one sheet per non-KPI visual (table + native chart, "Previous period" column when comparing), a Records sheet for the page dataset under the same filters and period (cap 50,000; above that 422), a Definitions sheet. With `visual=`: Summary + that visual's sheet + Definitions, no Records (hidden visual 403). Filename e.g. `Service_Overview_2026-10-01_to_2026-10-26.xlsx`. Writes an AuditLog row.
