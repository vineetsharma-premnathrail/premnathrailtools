# Reports as Power BI-style DASHBOARDS (replaces the "report builder" screen as the default)

Owner feedback (2026-10-26, on the built Reports page): "This is not what I wanted. I want data analysis in graphs like Power BI. What you built, people would need training to use. Make it like before (the simple page with counters and graphs) but like Power BI." So: NO group-by / measures / columns / saved-views controls in front of the user. Ready-made dashboards: slicers, KPI cards, charts, click-a-chart-to-filter-everything, "Show data", Excel export. Plain words, nothing to configure, zero training.

## The user experience (Power BI behaviour, plain words)
- Page = module dashboard with TABS for ready-made dashboard pages (Service: Overview, Engineers, Pending & Ageing, Timing, Customers & Machines, Billing [money only], Visits). Each page is a grid of visuals (cards) on one screen, 2-4 per row, readable on a laptop; on a phone they stack.
- Top bar (one row): page title, date range control (preset chips: This month, Last month, This quarter, This FY, Last 30 days, Custom from-to), "Compare with previous period" toggle (KPI cards show a small up/down change), a "Clear filters" button when any filter or chart selection is active, and "Export to Excel" (primary, top right).
- Slicer row under it: dropdown slicers with search and multi-select (for Service: Engineer, Customer, Machine, Service type, Priority, Status, Zone, Warranty/Chargeable). Chosen values show as small chips. Only the slicers listed for that page. Plain labels.
- KPI cards (6-8 per page): big number, label, small change vs previous period (green/red by `better`), tooltip with the plain definition.
- Visuals: donut, column (vertical bar), horizontal bar, line/column over time, stacked bar, and a "Top N" table. Each card: title, a small "..." menu with "Show data" (opens the records popup for what is shown) and "Export this to Excel". Hover tooltips with value and %, optional data labels.
- CROSS-FILTER (the Power BI feel): clicking a bar / slice / point selects it: that value is highlighted, every OTHER visual and KPI card on the page re-filters to it; clicking again, or the chip's x, clears it; Ctrl/Shift-click adds more values. A strip "Showing: Priority = Urgent x  Engineer = Rohit x" shows what is active. Slicers and chart selections combine (AND across fields, OR within a field).
- "Show data" opens the existing records popup (DrillSheet) with the same filters; clicking a row opens the record (service request, machine).
- Empty / loading / error states in plain words. A short one-line hint under the title of each page ("What this page shows").
- The old detailed screen (explorer: group-by, measures, columns, saved views) is NOT the default: keep it only as a last tab "Detailed data" that shows the record table (search, sort, paging, choose columns) and nothing else; no group-by / measures UI.

## Dashboard pages (Service, from the existing datasets; money/people items follow the existing permission rules)
All visuals use existing `sr` / `visit` dataset dimensions and measures (see backend/app/modules/erp/reporting.py). Date field default: opened (done for timing visuals as noted).
1. Overview: KPIs Total requests, Open now, Overdue now, Completed, Avg response (h), Avg resolution (days), On-time %, Come-backs. Visuals: Status (donut), Priority (column), Requests by month (column, last 12 months, compare line optional), Top issue categories (hbar, top 8), Service type (donut), Top 10 customers (hbar), Warranty vs chargeable (donut), Raised vs Completed by month (line).
2. Engineers (people figures; without the management switch show only the viewer's own figures and say so): KPIs Engineers with work, Completed, On-time %, Avg response (h), Avg resolution (days), Work hours, Overdue now. Visuals: Completed vs Pending vs Overdue by engineer (stacked hbar), Avg resolution by engineer (hbar), Completed per month for top 5 engineers (line), Work hours by engineer (hbar), Visits by engineer (column), engineer table (Top N table: Assigned, Completed, On-time %, Pending, Overdue).
3. Pending & Ageing (snapshot "as of today", date control disabled): KPIs Open, Overdue, Awaiting closure, Not assigned, Oldest open (days), Avg age (days). Visuals: Age buckets (column, stacked by priority), Pending by status (donut), Pending by engineer (hbar, people), Pending by customer (hbar), Overdue list (Top N table: SR, customer, machine, engineer, days overdue).
4. Timing: KPIs Avg response (h), Median resolution (days), P90 resolution (days), On-time %, Avg time to reach site (days). Visuals: Avg resolution by priority (column), Avg response by priority (column), Resolution by service type (hbar), Avg resolution by month (line), Response time by zone (hbar), On-time % by engineer (hbar, people).
5. Customers & Machines: KPIs Customers served, Machines serviced, Repeat-failure machines, Come-backs, Chargeable %. Visuals: Top 10 customers (hbar), Top 10 machines by requests (hbar), Repeat failures by machine (Top N table), Requests by zone (column), Requests by model (hbar), Warranty vs AMC vs chargeable (donut).
6. Billing (needs the money switch): KPIs Billed, To bill, Collected, Free jobs, Actual cost, Gross margin. Visuals: Billing status (donut), Billed by month (column), Cost breakdown (donut), Billed by customer (hbar), Margin by service type (hbar).
7. Visits: KPIs Visits, Days on site, Work hours, Travel hours, Km, Expenses (money). Visuals: Visits by month (column), Hours by engineer (hbar, people), Visits by customer (hbar), Signed % (donut), Arrival hour (column).
Visual specs are DATA, defined in backend (below), not hard-coded in the frontend.

## Backend (framework + Service definitions)
- Framework (`backend/app/core/reporting/`): add `DashboardDef(module, key, label, order, pages: list[DashboardPage])`, `DashboardPage(key, label, hint, date_mode range|snapshot, slicers: list[filter keys], kpis: list[VisualSpec], visuals: list[VisualSpec], money_page, people_page)`, `VisualSpec(id, kind kpi|donut|column|hbar|line|stacked_bar|table, title, hint/definition, dataset, group_by, group_by2, measure (one) or measures (stacked/table), top_n, sort, date_field, span 1..3, money, people, better, drill: which dimension a click filters (default = group_by), time_window e.g. last_12_months)`. `register_dashboard()`. The catalogue gets `dashboards[]` (pages with slicers/visual specs) for modules that have them; money/people pages and visuals are ABSENT when the viewer may not see them (same rules as reports).
- ONE batch endpoint: `POST /reports/{module}/dashboard/{page}` body `{date_field?, preset?, date_from?, date_to?, compare?, filters: {f_<key>: "a,b"}, visuals: [{id, filters?: {...per-visual overrides, e.g. drop the filter that this visual itself drives}}]}` -> `{page, period, filters_applied, results: {<visual id>: {labels, values (and per-series datasets), totals, compare, delta_pct, drill: {dimension, tokens per label}, row_count}}, kpis: {...}, notes}`. It loads each dataset ONCE per request (cache the loaded rows for the request) and evaluates all visuals in Python; same permission pipeline, data scope, money/people stripping, caps and error messages as the run endpoint. Selection by a visual's own dimension is excluded for that visual (Power BI behaviour: it stays full and highlights the selection) via the per-visual `filters` override sent by the client; also return `selected` flags if useful. Detail ("Show data") keeps using the existing run endpoint with `level=detail` and the drill filters. Export: `GET /reports/{module}/dashboard/{page}/export` -> the designed workbook: Summary sheet (title band, period, active filters, KPI scorecard) + one sheet per visual (table of labels and values, plus a native chart) + a Records sheet for the page's dataset with the same filters (capped as before) + Definitions; same styling as the current xlsx builder.
- Service (backend/app/modules/erp/reporting.py): register the Service dashboard with the 7 pages above using existing dimensions/measures; add dimensions/measures that are missing (e.g. a last-12-months bucket, top-N), flag money/people items correctly, give every KPI a plain definition and a `better` direction.
- Keep the existing run/options/export endpoints (the "Detailed data" tab and drill-down use them).

- Style: the app's glass cards, one toolbar row, same orange accent; charts use the existing palette; cards with equal heights, titles one line; phone: single column, slicers scroll horizontally inside their row (not the page).
- Remove from the default experience: Group by, Then by, Measures, Columns chooser, Saved views, Level switch. (Components may stay in the repo for the Detailed data tab but must not appear on dashboard pages.)
- Language: plain English, no analyst words ("dimension", "measure", "pivot"); never "SLA" (say "Target date").
- Tour `erpReports.ts` rewritten for the new page: tabs, date range, slicers, KPI cards, charts (click to filter), Show data, Export.
