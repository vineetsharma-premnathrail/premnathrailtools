# Maintenance — audit 2026-10-27

## High
1. **No permit-to-work on WOs converted from requests or generated by PM.** `permit_required` is never set on these paths (requests.py:268-282, service.py:469-488).
2. **The permit can be bypassed.** Resume does not check the permit (work_orders.py:397-408), and any editor can PATCH `permit_required=false`.
3. **A completed WO can be edited before close.** Type, root cause and action can be changed or cleared; the root-cause check runs only at completion (work_orders.py:310-329).
4. **Duplicate PRs.** Nothing stops a second PR from the same WO or the same spare. Spares ignores quantities already on order, so the daily alert invites a repeat PR (wo_procurement.py:83-177, spares.py:132, service.py:210-219).

## Medium
5. A PR raised from a WO has no Purpose or charge: it gets a fake project label and category OTH, which has no buyer, and SRV is missing (wo_procurement.py:119-153, WorkOrderPurchaseCard.tsx:19).
6. Cancelling a WO leaves its PRs/POs live (work_orders.py:541-565).
7. An outside-repair bill posted after close never reaches the job cost, and close does not check open service POs (procurement.py:61-65).
8. The AMC & Warranty list and its export ignore data scope (contracts.py:45-82).
9. A WO or PM plan can be created on an asset outside the user's scope (work_orders.py:254, pm_plans.py:186/373).
10. PM monthly due dates drift: the 31st becomes the 28th and never comes back (service.py:324-329, 642).
11. The job spares cost uses standard cost while Store issues at average, and returns post at today's cost (work_orders.py:639, 750) (verify).
12. Non-breakdown jobs can be completed and closed with nothing recorded (work_orders.py:425-447).
13. Opening a single WO and listing requests skip the tab permission (work_orders.py:302, requests.py:91).

## Low
14. A WO can be cancelled while its LOTO permit is still active.
15. Labour and spares can change after close-out was submitted, so the approval shows the old amount.
16. A cancelled machine-down job's downtime keeps growing.
17. Decommissioning an asset leaves its non-PM jobs and requests open.
18. A bad date gives a 500 (requests.py:280); PATCH with a null priority or type gives a 500 (verify).
19. The WO spare/service picker uses limit(200) before sorting and filtering, so items are missed (dashboard.py:212).
20. Lists are not sorted by code asc (WOs, requests, spares).
21. The frontend permission gates don't match the backend. The Spares "Raise PR" button is shown to users without the PR-create right, and the prefill has no Purpose.
22. Spares ignores scope, and "free stock" counts reserved stock as free.
23. /maintenance/lookups gives production-only users the full vendor master and the technician list.
24. 8 unused imports, and a stale settings docstring.

Clean: dialogs, portals, native select, signed links, Back pill, gear, store_item_id on lines, close-out via the central engine.
